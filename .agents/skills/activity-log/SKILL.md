# Activity log

Visible to administrators on **Settings → Activity log**
(`app/Filament/Resources/ActivityLogResource.php`). Entries are kept a year.

## Three kinds of entries

1. **Model changes** — `use App\Models\Concerns\RecordsActivity;` on the model.
   It logs created/updated/deleted with only the changed attributes
   (`logOnlyDirty`, empty updates skipped). Override when needed:
   - `activityLogAttributes()` — whitelist; **never include passwords or tokens**
     (see `User`);
   - `activityLogName()` — `AuditLog::LOG_RECORDS` (default) or `LOG_SCHEDULE`;
   - `shouldLogEvent()` — `UserEvent` logs only the approved schedule
     (`schedule_draft_id === null`); drafts are scratch work.
   Vendor models are extended to add the trait (`App\Models\Role`, wired in
   `config/permission.php`).

2. **Relation changes** — BelongsToMany syncs fire no model events.
   Create/edit pages use `App\Filament\Concerns\LogsRelationChanges` and list
   the relations in `loggedRelations()` (`['roles' => 'name', ...]`). Relation
   managers do the same with `->before()`/`->after()` on actions
   (see `SynergiesRelationManager`). Entry event: `relations_updated`.

3. **Operations** — one summary entry per business operation via
   `App\Support\AuditLog::record($event, $subject, $properties, $logName)`:
   `autogenerated`, `draft_created`, `draft_duplicated`, `draft_renamed`,
   `draft_deleted`, `draft_cleared`, `draft_approved`, `month_cleared`;
   auth listeners record `login`, `logout`, `login_failed` (email and IP, never
   the password) in `AppServiceProvider`.

## Bulk operations

Wrap work that creates or deletes many models in
`AuditLog::withoutModelLogs(...)` and record one summary afterwards. Query
builder `->delete()`/`->update()` never logs by itself — record a summary for it.

**Pitfall:** values filled inside the callback must be captured by reference
with a regular closure — `fn () => ...` captures by value, so a summary built
inside stays empty:

```php
$summary = [];
AuditLog::withoutModelLogs(function () use (&$summary): void {
    DB::transaction(function () use (&$summary): void { /* ... */ $summary = [...]; });
});
AuditLog::record('draft_approved', $draft, $summary);
```

## When adding a new event key

Add a label to `ActivityLogResource::eventLabels()` (and a new log name to
`logNameLabels()`), with translations in both `lang/*.json`. Field names and
values in entries are shown as stored, not translated.

## Pruning

`Activity::created` queues `App\Jobs\PruneActivityLog` at most once a day
(cache key `activity-log:pruning-dispatched`); the queue worker deletes entries
older than `activitylog.delete_records_older_than_days` in chunks. There is no
scheduler container; do not add one just for this.
